Workflow of WEB UI Server

    PXA1802 WEB Working Mechanism.pdf

​

​ The http socket communication between the front and back end of the existing scheme is used to pass XML data.

​ The Web-UI front-end (the code running in the browser) communicates through AJAX and http server, that is, using the http protocol, using the XML data format to interact with the server data.

The backend calls the processing functions of the corresponding module based on the XML file and the XML content. If it is a POST request , the backend saves the corresponding XML fields to the database, and then calls the corresponding module handler processing; if it is a GET request, the database may be called in the module's handler for access.
Combine examples to describe how Webserver works

​ The web method works as ajax call mode, because the server only supports GET/POST operations, so it can only issue these two kinds of http requests, after the URL when the request is issued, add the suffix after the URL.

WebServer receives the request to parse the URL:
(1) resolves the request to the get file request,

Read the webdata according to the request path and return the file.

    http://192.168.1.1/html/home_network/dhcp_settings.html

The request is a get file operation, reading the webdata html/home_network/dhcp_settings.html file.
What if I resolve to xml_action? The CGI,

The request will be judged as a cgi request, the processing process will be transferred to the cgi task, and then continue to resolve the url, module=get, the request is to get request, continue to parse the url, module=duster, the processing process into the duster module, parse the xml file, read the xml file's individual subspaces, enter the corresponding duster submodules, and the relevant processing, each module submodule has two main processing functions, module_post_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_get_
(3) Get operations: such as

http://192.168.1.1/xml_action.cgi? method=get&module=duster&file=lan

The subspace name is lan, and after comparison, it enters the lan_post_get() function, which gets the value of each node in lan.xml in the database psm and returns it to the webserver.

Web lan.js retrieves the returned lan.xml, gets the node value, and generates the page.
(4) Set operations:

Modify the relevant data on the web page, then post the modified xml value to the webserver, and finally into the post_set() function of the module near the duster.

For example, if you modify dhcp ip start to 10 on the web, and the end is 150, js detects the relevant values of the modification, generates lan.xml that will post to the webserver, and add xml_action.cgi at the end of the url. The method=set&module=duster&file=lan field will generate lan.xml POST to the server. Finally, go to lan_post_set, which detects the relevant modification values and is related to the processing.

After the post, JS will make a get request and the results of the relevant changes will be displayed on the web interface.

AT*MRD_IMEI=W,0101,12NOV2010,012 34567890123

 Defined values
 <a>:
 W:write IMEI to RD
 D: delete IMEI from RD
 R: read IMEI from RD
Luat LTE Module AT Command User Manual
 <v>: Version string, must be 4 ASCII strings like 0201, 0311, etc
 <d>: Date string, must be 9 ASCII strings like 06JUN2010
 <s>: The ASCII strings of IMEI, must be 14 or 15 or 16 digits, must terminated with NULL
